<details>
<summary><b>◈ the longer pathway →</b></summary>
<br/>
I like problems where the constraints are physical, not just abstract — a fixed millisecond budget, a real memory ceiling, a camera feeding frames faster than a naive pipeline can consume them. On-device ML is that, all the time. You can't hand-wave latency away with a bigger cloud instance; you either make it fit, or it doesn't ship.
 
That's most of what I do: take a model that works in a notebook and make it work in a hand, at the edge, offline. If you're building anything that has to *see* and *decide* on the device itself — I'm probably the right kind of stubborn for it.
